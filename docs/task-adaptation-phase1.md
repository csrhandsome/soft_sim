本轮优先推进 goal 的阶段 0 和阶段 1；尚未完成 42 个基础任务，也未实现后续 YAML 全量入口。

只有原场景中的完整物理运行才构成适配完成证据，代码接入数不等于适配完成数或成功数。

## 共用执行路径

任务适配器描述有上限的操作序列，并依据每步重新导出的几何解析目标。抓取、试抬、携物转移、
放置、松爪、撤离、回位共用原规划与采集代码。每步保存 `placement.json`、完整场景、计划和
执行检查点；任务最后仍调用原 RewardManager，不改动上游任务或条件。

规划新增 `--place-pose`，使用物体的完整 SE(3) 目标，同时变换抓取 TCP、携带物和松爪后的
障碍物；目标朝向不会被丢弃。场景物体保留三角网格，避免容器凸包封闭入口；另一机械臂仍为
保守碰撞代理。不能通过忽略容器、家具、其他物体或夹具碰撞来获得计划。

## 输入与正式数据

`download-assets --task <task> --seed <seed>` 下载官方保存布局及其精确模型，保留来源、哈希、
已下载文件和失败原因。默认下载预算有限；源缺失或超预算时明确失败，不替换物体或自动改 seed。
运行前检查布局依赖，运行中保存 `inputs/layout.json` 和 `inputs/provenance.json`。

正式成功数据直接写入 `data/datasets/<task>/`；失败和直接改关节状态的诊断录制使用独立路径。
数字和分类任务预留固定对象槽位，`task_object_valid` 标记当前输入实际存在的对象；不存在的槽位
使用零位置和单位四元数，其值不能当作真实物体。材料、安装、对象标签及成功筛选策略也纳入集合兼容检查。

## 已知限制

目前仍使用指定的一台活动臂，并将另一台保持为障碍物；没有用自动瞬移或关闭碰撞绕过跨工作区
问题。双臂协调、接触后修正、容器内多物体紧凑装箱仍需后续扩展；当前无法找到可行计划或实际
放置不稳定时，记录该输入失败并继续覆盖其他任务。底板暂放点、套娃目标行和 T 暂放点是操作
规划目标，不改变原场景；被其他物体占用时必须通过原碰撞检查，否则失败。

完成的运行，规划通过或启动仿真不能记作完整任务验证。
