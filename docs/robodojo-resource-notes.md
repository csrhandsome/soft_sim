# RoboDojo 资源需求与软指优化重点

记录日期：2026-11-14。当前优先在本地单机优化，保留 RoboDojo 和 IsaacLab 的第三方
源码；实验通过本项目自己的软指实现、配置适配和独立测试入口完成。

## 公开资料能说明什么

本轮检索没有找到直接针对“生成示范数据为什么这么耗资源”的明确投诉，找到以下相关
资料。这不是对全部社区讨论的穷尽检索，也不能据此认定 RoboDojo 源码有性能问题。

- [官方 issue #37：示范数据生成／扩展流水线](https://github.com/RoboDojo-Benchmark/RoboDojo/issues/37)
  询问 SFT 示范数据生成和扩展脚本何时开源。官方仓库目前主要面向评测；已有评测入口
  不等于已经公开了成熟的数据生产流水线。
- [官方论文 §6.3.1](https://arxiv.org/html/2607.04434v1#S6.SS3.SSS1)
  的吞吐实验使用 8 张 RTX 4090，每卡一个 RoboDojo 进程、10 个并行环境。这是大规模
  评测的实验设置，不能解释为生成一条示范必须使用这些资源；文中的 interaction 吞吐
  也不能直接当作本项目的 1 ms 物理步吞吐。
- [Embodied First Exam 的直接接入实测](https://github.com/mll-lab-nu/embodied-first-exam/blob/main/tasks/robodojo/README.md#compute-resources-scriptstask_resourcestoml)
  记录多个任务每进程约 4.6–8.4 GB 显存，最重液体场景约 9–9.6 GiB。不同任务、版本、
  相机和资源计量口径有所不同，但这说明原生 Isaac 场景本身就可能占用数 GB 显存。
- [官方 Docker 排障说明](https://github.com/RoboDojo-Benchmark/RoboDojo/blob/main/docker/README.md#6-troubleshooting)
  提到首次运行可能因 Warp 编译和扩展下载出现 CPU 高、GPU 低、等待数分钟。这解释
  冷启动问题，不能直接解释已经预热后的每个物理步为何耗时约 34 ms。

因此，公开资料不支持“RoboDojo 源码一定有问题”的结论。我们的场景还额外加入四根
FEM 软指，不能把原生任务的吞吐数字直接移用到软指采集。

## 本项目已有的计时证据

同一条 X5 抓取计划，1 ms 步长、四根软指、80 次迭代、三路相机，完整执行 13,440 步，
采集 268 组画面。证据：
[三次完整回放报告](../artifacts/cache/benchmarks/follow_replay_20261114T132101Z/comparison.json)。

| 路径 | 控制＋物理平均 ms/步 | 完整采集 s |
|---|---:|---:|
| CPU 更新 | 35.070 | 647.248 |
| CPU 相同路径重复 | 35.351 | 649.812 |
| GPU 位姿／目标更新 | 34.401 | 637.576 |

控制＋物理约占完整采集时间的 73%；其余约 27% 是采样、校验和记录，包含渲染、CPU
处理与暂存，不是纯渲染时间。因此，下一阶段重点放在软指求解、网格和接触是合理的。
但目前还没有把 FEM、刚体求解、接触和框架逐项拆开，不能宣称 FEM 已被证明占了 73%。

GPU 更新相对两次 CPU 平均值只带来约 2.35% 的单步加速、约 1.7% 的整体加速。
这项改动消除了更新链中的主机往返，但不是所需的大幅提速，现阶段仍保留为可选路径。
三次都抓取成功。GPU 与 CPU 的节点最大距离约 0.73／0.93 mm；两次 CPU 自身重复的
差异约 0.93／0.90 mm，不能要求求解后节点逐位相同。最终抬升差异约 0.0375 mm，
CPU 自身重复的抬升差异约 0.0368 mm。它们说明对照结果与重复波动接近，不证明材料
标定或 FEM 的实物准确性。详细测试规则见 [GPU 更新对照](gpu-follow-performance.md)。

另一个待测因素是本项目 [配置适配](../src/soft_sim/sim/robodojo.py) 将场景位置迭代下限
绑定到了软指迭代数。全局下限 80 是我们的适配配置；RoboDojo 原生默认下限为 1。
实验需要区分软体自身迭代数与场景下限，避免同时改动两个因素后误判原因。这不要求修改
第三方源码，也不预先保证降低场景下限会提速或保持物理结果。

## 300 步无渲染短测

随后在完整原生场景中保持关节目标不动，预热 50 步、计时 300 步，计时区间不渲染。
这是筛选成本和静态形变的短测，不是完整抓取效果验证。证据：
[短测报告](../artifacts/cache/benchmarks/physics_cost_20261114T140719Z/comparison.json)。

| 软指请求迭代数 | 场景迭代下限 | 外层缓存更新 | 中位 ms/步 |
|---|---|---|---:|
| 80 | 80 | 保留 | 27.974 |
| 80 | 80 | 省略 | 28.095 |
| 80 | 8 | 省略 | 28.082 |
| 40 | 80 | 省略 | 28.033 |
| 40 | 8 | 省略 | 15.338 |

前几项的差异没有显示有意义的提速，因而不据此修改生产更新链或场景配置。场景下限 80
会覆盖软指的 40 次请求；只有允许实际降低软指迭代时，耗时才显著下降。这项控制实验
进一步支持将优化重点放在软指迭代相关成本上。

在场景下限都为 8、输入相同的 80／40 对照中，40 次耗时减少约 45.4%，但四指末帧
重力变形幅度分别增加约 2.9%、9.5%、6.4%、11.5%，安装坐标系内最大节点距离约
0.25、0.45、0.36、0.48 mm，未通过 5% 的静态变形幅度筛选。这个阈值是保守筛选规则，
不是实物精度声明；末帧快照也不能替代时间平均和接触验证。当前保留原有 80 次配置，
不将 40 次候选推进到昂贵的完整回放。

## 渐进验证顺序

1. 每轮只比较一个变量，优先两组 200–300 步，保持相同初始状态、输入和计时范围；
   排除初始化、编译和渲染。先查看稳定区间的耗时及变形差异。
2. 保持软指 80 次时，先筛选本项目更新链和配置中的可避免开销。约 2% 的收益不足以
   支持反复执行昂贵的完整回放；后续优先推进有约 15% 以上稳定单步收益的候选。
3. 80→40 次作为独立候选实验，明确场景迭代下限，避免实际仍被强制运行 80 次。
   比较稳定后的下沉／弯曲、节点形状、Jacobian、夹持误差，再做短接触、保持和抬升
   检查。不能只用“最终还能抓起来”判定物理质量相同。
4. 短测确实更快、物理差异也可接受后，才运行完整抓取回放。只有单机优化取得明显
   收益后，再考虑 5090 和并行采集。

短测默认只有基线和一个候选；`SOFT_SIM_PHYSICS_CANDIDATE_ITERATIONS` 可指定候选
迭代数，`SOFT_SIM_PHYSICS_PROBE_STEPS` 指定计时步数。较宽的五组排查只有显式设置
`SOFT_SIM_PHYSICS_EXTENDED=1` 才运行。

```bash
OMNI_KIT_ACCEPT_EULA=YES OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
SOFT_SIM_PHYSICS_SOURCE_RUN=20261114T091003Z_general-pickup_s22_72e465 \
SOFT_SIM_PHYSICS_PROBE_STEPS=200 SOFT_SIM_PHYSICS_CANDIDATE_ITERATIONS=40 \
python scripts/run.py test --group gpu-physics --verbose
```

重新核验已有短测证据，不启动 Isaac Sim：

```bash
SOFT_SIM_PHYSICS_REPORT=artifacts/cache/benchmarks/physics_cost_20261114T140719Z/comparison.json \
python scripts/run.py test --group gpu-physics --verbose
```

已知的小单元初始化告警仍须另行核查，见
[贴合网格的数值边界](conforming-fem-2026-11-12.md#数值边界)。本轮性能实验不消除该限制。

## 保持 80 次的首轮 profiling 与网格筛选

2026-11-14，在 RTX 4070 Laptop GPU 上完成一轮预热后 profiling 和一组独立无 profiler
网格对照。所有运行都保持四根软指、1 ms 步长、80 次软指迭代、场景下限 80，以及原有
双缓存更新链。没有修改第三方源码、生产网格或默认配置。

### 预热后 GPU 时间线

证据：[profiling 摘要](../artifacts/cache/benchmarks/physics80_20261114T142806Z/profile_summary.json)、
[完整 Nsight 记录](../artifacts/cache/benchmarks/physics80_20261114T142806Z/profile80.nsys-rep)、
[运行清单与源码哈希](../artifacts/cache/benchmarks/physics80_20261114T142806Z/manifest.json)。

通过 `--profile` 在预热 50 步后，以 CUDA profiler API 和 NVTX 只捕获后续 200 个无渲染
物理步。该窗口约 5.960 s，CUDA 内核及内存操作时间区间取并集约 4.846 s，占窗口
81.3%；这表示存在 GPU 活动，不等于 SM 利用率。共记录 524,200 个内核，平均每步
2,621 个。按内核耗时求和，`sb_` 前缀占 42.7%，`solveStaticBlockTGS` 占 37.4%，
关节相关命名前缀占 14.3%。两个主要内核分别为 `solveStaticBlockTGS`（37.4%）和
`sb_gm_cp_solveTetrahedronsPartitionLaunch`（32.3%）。

这些是按内核名称归组的线索，不是 FEM、碰撞、刚体的严格墙钟时间拆分。多个 stream
的执行重叠，内核耗时和约 7.543 s 大于窗口长度，不能把这些百分比直接乘到总耗时或
用作 Amdahl 加速预测。结果支持同时关注软体与其他 TGS 求解工作，不能宣称 FEM
占据全部迭代成本。profiler 下的 29.66 ms/步不用于性能筛选。

### 一个候选、两组各 250 步

先离线检查了仅放宽 TetGen 最大单元体积的路径：4→5 mm 参数只将每指四面体从
33,417 降到 33,046，减少 1.1%，未进入 GPU 对照。正式候选保持 4 mm 最大体积参数
与 10° 最小二面角请求，只将 TetGen 半径边长比上限从 1.4 放宽到 1.6，以减少质量
细分产生的单元。这是放宽形状质量约束，不是声称生成了更高质量的单元。

| 项目 | 现有基线 | 半径边长比 1.6 候选 |
|---|---:|---:|
| 每指节点 | 8,491 | 7,234 |
| 每指四面体 | 33,417 | 27,588 |
| 无 profiler 中位 ms/步 | 28.353 | 23.877 |
| 参考体积相对 STL 误差 | +0.000745% | +0.000720% |
| STL 外单元中心数 | 0 | 0 |

单元减少 17.4%，本次单步耗时减少 15.8%。两组各预热 50 步、计时 250 步，每 25 步在
计时外保存一次节点快照。每组按 50 步分为五窗：基线中位耗时 28.19–28.46 ms，候选
23.68–24.09 ms。这是一组 A/B，不证明跨运行重复性或接触阶段的加速。

不同网格不能逐节点相减。本轮将两套位移分别插值到同一 STL 顶点，排除固定区后每指
比较 340 个共同表面点，并核验绑定未发生明显外插。在计时第 150–250 步的五个检查点：

| 指头（arm / side） | 基线平均最大位移 mm | 候选平均最大位移 mm | 幅度平均变化 | 最大共同点距离 mm |
|---|---:|---:|---:|---:|
| 0 / 0 | 3.324 | 2.782 | −16.3% | 0.661 |
| 0 / 1 | 3.240 | 2.609 | −19.5% | 0.662 |
| 1 / 0 | 3.287 | 2.772 | −15.7% | 0.657 |
| 1 / 1 | 3.236 | 2.610 | −19.3% | 0.791 |

全部检查点节点有限、Jacobian 为正、固定区误差小于 0.000404 mm，但形变幅度已经
超过原 5% 筛选门槛；共同点位移 RMS 差相对基线 RMS 的后段最大值也达约 16.6%–19.9%。
因此候选未通过物理筛选，不进行昂贵的性能复测或完整回放。共同 STL 顶点不是面积
均匀采样；短窗口也没有证明已经达到静态平衡，不能将以上变化直接称为实物刚度误差。

数值边界仍存在：每指 tensor 报告的零自由单元 rest pose 数量基线为 11,856、候选
9,301。两套网格均触发既有小单元初始化告警。不能据此认定所有这些单元都失效，也不能
将形变差全部归因于迭代收敛改善；下一轮应优先独立核查这条边界，或仅改变碰撞表示，
避免继续把力学网格粗化当作等价优化。两组实际固定区高度差约 0.0031 mm，也已保留在
报告中。

证据：[网格审计](../artifacts/cache/benchmarks/physics80_20261114T142806Z/mesh_audit.json)、
[短测与共同表面对照](../artifacts/cache/benchmarks/physics80_20261114T142806Z/mesh_comparison/comparison.json)。
运行脚本、源文件快照、日志、原始快照、Nsight CSV 和分析脚本均保存在同一目录。
94 项单元测试通过；这不代表被拒绝的物理候选通过了验收。

## 80 次固定区消元的完整回放补测（2026-11-15）

后续已筛选分区、线程、碰撞表示、网格质量、节点排序和时间步等方案，最终推进的是
保留原自由单元与完整碰撞网格的固定区消元。两次完整候选均抓取成功，保持 80 次迭代
和 1 ms 步长；控制＋物理耗时减少约 28.7%～29.7%，含三相机的采集耗时减少约
21.3%～22.2%。这小于无渲染短测的约 34%。

保持阶段平均形变幅度差最大约 4.34%／4.66%，但第二次候选在 11.60 s 出现一个记录帧
的节点形状距离 1.742 mm，超过既定 1.5 mm 上限。因此提速已复现，完整物理筛选尚未
全部通过，暂不切换默认配置。首次与独立复跑的三视角视频均保留在 `data/generated/videos/` 供人工判断。
完整方法表、阶段形变、局部体积比审计、重复波动和视频见
[80 次评估报告](softfinger-80iter-evaluation.md)。
